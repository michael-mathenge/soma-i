## MVP1 review and approval workflow - 2026-10-21

- Branch feat/review-workflow was created from feat/metadata-only-content. The publication pipeline has always required dated owner review evidence for every item, for every publisher and for every feed, but no command existed to record it, so the only way to approve a path was to write rows by hand in a database shell. The publisher map in the discovery rules was empty, so nothing could be published at all. This adds the tooling to record that evidence; it does not approve anything.
- Three commands were added. approve_feeds records feed access, metadata reuse and the separate excerpt reuse decision in the feed registry. approve_publishers records publisher reuse permission and independence in the discovery rules. review_resources records the per item review, which confirms free access, English content, the author and the evergreen classification, and writes the content fingerprint the pipeline checks.
- Every command is fail-closed and validates the whole file before it writes anything. A command refuses a missing field, a review that is not dated, a review that is not current, a review that lasts longer than ninety days, an item that was not ingested, a feed without permission evidence, a publisher that is not recorded or not independent, a publisher that is not current, an item outside the publisher domains, an evergreen item without a reason, and two publishers that share a domain, because those are not two independent publishers. A dry run reports what would change and writes nothing.
- The reviewed files hold the owner's decisions, so they live outside the repository. The commands take an explicit output path for the same reason, and the tests target a temporary file. An earlier version of the publisher test wrote to the repository rules file by accident; that was found, reverted, and the command now takes an explicit output path so a test cannot modify reviewed content.
- The excerpt reuse permission is now a separate decision rather than part of feed access. The permission gate previously required feed access, metadata reuse and excerpt reuse together, which meant a publisher that permitted linking and attribution but not republication could not be used at all. The gate now requires feed access and metadata reuse, and requires excerpt reuse to be recorded as an explicit true or false. Content is published as title, publisher and date by default, so a publisher that does not grant excerpt reuse is fully usable.
